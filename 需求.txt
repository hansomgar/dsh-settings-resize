任务：给 DSH 桌面版写一个本地客户端插件 dsh-settings-resize，在「设置 → 通用设置」里用三个滑动条
调节设置弹窗的宽度、高度和透明度，改完立即生效，并且重启后仍然保留。

本文件是【已实现版本的完整规格】。照此文档实现，应得到一致的效果与行为。
文档中给出的代码为最终生效代码，可直接复制使用。

================================================================================
一、最终效果（用户看到的样子，即验收标准）
================================================================================

1. 打开 DSH → 点左下角设置 → 左侧导航选中「通用」→ 向下滚动，
   在「链接打开方式」与「输入框回车行为」两项之间，出现本插件的一整块区域：

   设置窗口尺寸
   拖动滑块调节设置弹窗的宽高与透明度，改动立刻生效并被记住。

   宽度    [========|=================]   [ 800 ] px
   高度    [========|=================]   [ 800 ] px
   透明度  [|==========================]   [   0 ] %

   当前：800px × 800px · 透明度 0%          [ 恢复默认 ]

   透明度只让弹窗底衬变透，文字与控件保持清晰；拖到 100% 时底衬完全透明，
   弹窗边缘仍保留一圈描边，方便定位。窗口较小时宽高会自动缩小，不会超出屏幕。

   区域底部有一条 .5px 分隔线（--dsw-alias-border-l2），与设置页其他条目观感一致。

2. 拖动「宽度」滑块，正在打开的设置弹窗当场变宽；拖「高度」当场变高；
   拖「透明度」弹窗底衬当场变透。不需要点保存，不需要重启。

3. 三个滑块各自右侧有数字输入框，可直接键入精确数值。输入非数字时提示「请输入数字」；
   输入越界数字时按边界截断，并在下方显示黄色提示「已按范围截断：640–2400px」。

4. 底部「当前：1200px × 900px · 透明度 20%」实时反映生效值。
   三个值【全部】等于默认值（800/800/0）时，「恢复默认」按钮置灰不可点。

5. 点「恢复默认」→ 弹窗回到 800 × 800、完全不透明（透明度 0%）。

6. 完全退出 DSH 再启动，尺寸与透明度保持上次的选择。

7. 窗口从大缩到小时，弹窗不会溢出屏幕：宽度被夹到 100vw - 48px，
   高度被夹到 100vh - 2 * max(24px, var(--dsh-frame-overlay-top, 24px))。

8. 只影响设置弹窗。其他弹窗（如快捷键编辑）、面板、页面完全不受影响。

9. 禁用插件后，设置弹窗立即回到 DSH 原始的 800 × 800、不透明、无描边，不留任何残留
   （style 标签、四个 CSS 变量、slot 注册、locale 字典全部撤销）。

10. 界面文案中英双语，跟随 DSH 的「设置 → 通用 → 语言」切换，无需重启：
    中文显示「设置窗口尺寸 / 宽度 / 高度 / 透明度 / 恢复默认」，
    英文显示 Settings window size / Width / Height / Transparency / Reset to default。
    所有文案来自 client.js 内的 zh / en 两份字典，组件里不得内联任何界面文字。

================================================================================
三、交互规格
================================================================================

三个滑块，参数必须与下表一致：

  名称      状态字段        min   max   step  单位  默认
  宽度      width            640   2400   10    px     800
  高度      height           480   2160   10    px     800
  透明度    transparency       0    100    1    %      0

- 透明度语义：0% = 完全不透明（默认），100% = 底衬完全透明。
- 每个滑块右侧紧跟一个 <input type="number">，宽 66px，右对齐，等宽数字，
  并隐藏 webkit 的上下微调按钮。
- 滑块 <input type="range"> 与数字框共享同一个值；拖动滑块时数字框同步，反之亦然。
- 数字框输入规则：
    · 空串        → 忽略，不写入，清空提示
    · 非数字      → 提示「请输入数字」，不写入
    · 数字        → 四舍五入取整，按 [min,max] 截断
    · 发生截断    → 提示「已按范围截断：{min}–{max}{单位}」
    · 正常         → 清空提示
  onBlur 时清空草稿态（draft），回到受控值。
- 「恢复默认」在三个值全部等于默认值时 disabled，样式 opacity .45 + cursor default。
- 「恢复默认」写入 {width:800, height:800, transparency:0} 并清空提示。
- 所有改动同时做两件事：(1) 立刻写 CSS 变量；(2) 写 localStorage。
- 因为一次指针拖动可能在同一 tick 内连续触发多次更新，
  组件用 useRef 保存“最新生效值”，下一次编辑基于 ref 而非本次渲染闭包，
  否则快速拖动时宽度和高度会互相覆盖。

================================================================================
四、数据与持久化
================================================================================

localStorage key：dsh.settingsResize.v1
值（JSON 字符串，字段顺序固定）：

  {"width":1200,"height":900,"heightUnit":"px","transparency":20}

- heightUnit 字段永远写 "px"（原因见第五节）。
- 读取时对任何输入做归一化（normalize），任何异常都不得抛错：
    · 非对象 / null / JSON 解析失败 → 全部取默认值
    · width 缺失   → 800；非数字 → 800；取整后夹到 [640,2400]
    · height 缺失  → 800；非数字 → 800；取整后夹到 [480,2160]
    · transparency 缺失 → 0；非数字 → 0；取整后夹到 [0,100]
    · 兼容老记录里可能出现的 w / h 字段名
    · 兼容老记录的 heightUnit:"vh"：一次性换算成像素
      height = height * (window.innerHeight || 800) / 100
- 写 localStorage 失败（配额满/被禁）不得抛错，只是本次不持久化。

CSS 变量映射（写在 document.documentElement.style 上，即 html 行内样式）：

  --dsh-settings-w     = width + 'px'
  --dsh-settings-h     = height + 'px'
  --dsh-settings-alpha = (100 - transparency) + '%'    ← 底衬不透明度，是透明度的补值
  --dsh-settings-edge  = transparency + '%'            ← 边缘描边强度，等于透明度

  【关键】滑块量的是“透明度”，CSS 存的是“不透明度”的补值。两者不要弄反。

四之二、中英文双语（i18n）
================================================================================

DSH 内置语言只有 zh 与 en 两个（源码 LOCALE_IDS = ["zh", "en"]）。
本插件用 DSH 的 locale 服务做双语，不要自己读浏览器语言、也不要写死判断。

客户端写法（client.js 内，apply 中）：

  const NS = 'dsh-settings-resize'          // 与 cordis.patch.yml 的 id 相同
  const zh = { title: '设置窗口尺寸', ... }   // 完整中文词典
  const en = { title: 'Settings window size', ... }  // 完整英文词典

  const locale = ctx.get('locale')          // 可选依赖，用 get 而非 inject
  if (locale !== undefined) {
    ctx.effect(() => locale.register(NS, { zh: zh, en: en }), '...: zh/en strings')
  }

  ctx.slots.register({
    name: 'settings.general.item',
    id: 'settings-resize',
    order: 18,
    locale: NS,                              // ← 关键：声明命名空间
    label: () => locale === undefined ? 'Settings window size' : locale.bind(NS)('title'),
  }, Section)

  // 组件里通过 props.t 取文案：
  function Section(props) {
    const t = props.t
    ... t('title') ...
    ... t('current', { width, height, transparency }) ...
  }

机制要点（读源码确认，不要凭猜测改）：
1. register(ns, {zh, en}) 是「带类型的对象形式」，要求两个内置 locale 都给全。
   少一个键会直接编译报错——这正是我们想要的：不可能出现半翻译。
2. slot 注册里给了 locale: NS 之后，框架会向组件注入 t（PropsLocale），
   并在语言切换时重新渲染该行，组件不需要自己订阅。
3. t 支持 {name} 占位符插值：
     template.replace(/\{(\w+)\}/g, (m, name) => name in params ? String(params[name]) : m)
   所以 '当前：{width}px × {height}px · 透明度 {transparency}%' 可以正常拼接。
4. bind(ns) 返回的函数按命名空间缓存、引用稳定，可以在 label 里反复调用。
5. 查找顺序：当前命名空间走生效语言的 fallback 链 → common 命名空间同样走一遍 → 最后显示 key 本身。
   因此字典里漏掉某个 key 时，界面上会直接出现英文 key（如 noticeInvalid），
   一眼就能发现，不会静默显示空白。

【禁止】
- 不要在组件里内联中文字符串（会永远显示中文，切英文时不变）。
- 不要用 navigator.language 自行判断语言。
- 不要只注册一个语言。

文案对照表（改文案时两边一起改，键名必须完全对应）：

  键名              中文                                        英文
  title             设置窗口尺寸                                Settings window size
  description       拖动滑块调节设置弹窗的宽高与透明度，改动立刻生效并被记住。
                    Drag the sliders to resize the Settings dialog and adjust its transparency. Changes apply immediately and are remembered.
  width             宽度                                        Width
  height            高度                                        Height
  transparency      透明度                                      Transparency
  slider            {label}滑动条                               {label} slider
  field             {label}（{unit}）                           {label} ({unit})
  unitPx            像素                                        px
  unitPercent       百分比                                      %
  current           当前：{width}px × {height}px · 透明度 {transparency}%
                    Current: {width}px × {height}px · transparency {transparency}%
  reset             恢复默认                                    Reset to default
  noticeInvalid     请输入数字                                  Enter a number
  noticeClamped     已按范围截断：{min}–{max}{unit}             Clamped to {min}–{max}{unit}
  footnote          透明度只让弹窗底衬变透，文字与控件保持清晰；…   Transparency fades the dialog surface only, so text and controls stay sharp. …

================================================================================
四之三、【已修复的 bug】切回中文不生效（必须按此实现，否则会重现）
================================================================================

现象：在「设置 → 通用 → 语言」里从中文切到英文，本插件的行实时变英文；
再切回中文，本插件的行仍然是英文，不跟着变。其他内置设置项正常。

根因（读 LocaleRuntime 源码 + 用真实服务复现确认）：

  register(ns, { zh, en }) 是「单一占用者」语义：
    for (const [locale] of pairs)
      if (locales.has(localeKey(locale)))
        throw new Error(`locale namespace "ns" already has locale "zh"`)

  也就是说：同一个 (命名空间, 语言) 只能注册一次，重复注册直接抛错。
  而 locale 服务不暴露任何撤销 API，唯一释放途径就是 register 返回的 disposer。

  于是当 apply 被第二次执行（HMR 重载、或旧 fiber 的清理尚未执行就重新 apply）时：
    1. 上一次注册的 zh/en 还占着命名空间；
    2. 新的 register 抛错；
    3. 这个 throw 让整个 locale effect 失败，新字典没进去；
    4. 更糟的是旧字典此时可能已被旧 fiber 清掉；
    5. 结果：命名空间里没有 zh，查找沿 fallback 链落到 en。
  → 英文能显示（en 命中），中文永远显示不出来（zh 缺失，回落到 en）。

  这解释了「单向切换」这个看似诡异的现象：不是渲染没刷新，是字典丢了。

修复（client.js 里已有，不要改回裸 register）：

  const DISPOSER_KEY = '__dshSettingsResizeLocale'

  function releaseDictionaries() {
    const host = typeof globalThis !== 'undefined' ? globalThis : undefined
    if (host === undefined) return
    const previous = host[DISPOSER_KEY]
    if (typeof previous !== 'function') return
    delete host[DISPOSER_KEY]
    try { previous() } catch {}
  }

  ctx.effect(() => {
    releaseDictionaries()                       // ← 先释放上一代留下的占用
    const dispose = locale.register(NS, { zh, en })
    const host = globalThis
    host[DISPOSER_KEY] = dispose                // ← 挂在全局，模块重载也不丢
    return () => {
      // 只有仍持有占用的那一代才能释放；
      // 退休 fiber 的清理可能晚于新一代的注册，无条件释放会删掉新字典。
      const owner = host[DISPOSER_KEY] === dispose
      if (owner) { delete host[DISPOSER_KEY]; dispose() }
    }
  }, 'dsh-settings-resize: zh/en strings')

三个关键点，缺一不可：

1) disposer 必须挂在 globalThis，不能用模块级变量。
   HMR 会重新执行整个模块，模块级变量被重置为 undefined，
   而上一代的占用仍然存活 —— 那样就永远释放不掉，必然重现本 bug。

2) 注册前必须先 releaseDictionaries()，否则重复注册抛错。

3) 清理时必须判断「自己是否仍是 owner」再释放。
   重载时新一代先 apply 并写入 globalThis，
   随后退休 fiber 的清理才执行；若它无条件 dispose()，
   会把新一代刚注册的字典删掉，表现同样是「切回中文失效」。

验证方式（test/repro-hmr.cjs，11 项断言）：
  它从 app.asar 里抽出真实的 LocaleRuntime 类来跑，覆盖三个场景：
    A 普通切换：zh→en→zh
    B HMR 重载：新一代 apply 后，退休旧 fiber，再双向切换
    C 残留占用：globalThis 上的 disposer 被抹掉（模拟模块重置）后再次 apply
  已实测：把修复改回裸 register()，场景 B 会直接抛出
    'locale namespace "dsh-settings-resize" already has locale "zh"'
  说明这个测试确实能抓住本 bug，不是摆设。


================================================================================
五、为什么砍掉单位下拉（记录决策，勿改回）
================================================================================

最初设想是让高度支持 px/vh 两种单位（数字框 + 单位下拉）。实际实现放弃了它，原因：

1. 高度已经由 max-height: calc(100vh - 2 * max(...)) 兜底，窗口缩小时自动夹住，
   vh 能提供的“自适应”能力已被覆盖，再加单位切换是重复能力。
2. px/vh 混用会让滑块语义含混：同一个滑块位置在两种单位下代表不同视觉高度，
   「当前：1200px × 90vh」这类展示也难以和滑块位置对齐。
3. 单一像素单位让存储结构、归一化、边界提示都只需要一套逻辑。

因此：高度只有 px，滑块 min=480 / max=2160 / step=10。
但 normalize 仍保留对 heightUnit:"vh" 老记录的换算，避免历史数据出错。

----------- 三条实现要点，必须理解，否则做不出同样效果 -----------

1) !important 是必需的。
   原规则与我们的规则同为属性选择器/类选择器这一档优先级，
   不加 !important 会被 CSS Modules 生成的 .wCInkW_panel 压住。

2) 透明度必须只作用在【底衬】，不能给面板加 opacity。
   如果写 opacity: 0.5，面板里所有文字、图标、导航、按钮会一起变淡，
   调到 50% 基本没法读，效果完全不对。
   正确做法是用 color-mix 把背景 token 向 transparent 稀释，
   文字与控件保持 100% 不透明。这是本插件最关键的实现细节。

3) 100% 透明度时用 outline 补一圈边，而不是 border。
   拖到 100% 时底衬完全透明，只剩阴影；为了让弹窗还能被定位、
   关闭按钮还能找到，加一圈随透明度增强的描边：
   0% 时不画（保持 DSH 原观感），100% 时最强，中间线性过渡。
   用 outline 而不是 border，是因为 outline 不占布局盒，
   设定的宽度就是实测宽度，不会因为加了边框而缩水 1px。
   配合 outline-offset: -1px 让描边画在面板内侧。

          ),
        ),
        h('div', { className: 'dsh-settings-resize-desc' }, t('footnote')),
      )
    }

    /**
     * Drop dictionaries an earlier generation of this module registered. The disposer is
     * parked on `globalThis` precisely because an HMR reload resets this module's scope.
     */
    function releaseDictionaries() {
      const host = typeof globalThis !== 'undefined' ? globalThis : undefined
      if (host === undefined) return
      const previous = host[DISPOSER_KEY]
      if (typeof previous !== 'function') return
      delete host[DISPOSER_KEY]
      try {
        previous()
      } catch {
        // A disposer from a torn-down generation may already have run; the claim is what
        // matters, and the register call below re-establishes it.
      }
    }

    function apply(ctx) {
      // The CSS module builds a hashed class for the panel; the data attribute is the only
      // stable handle, so every rule above selects on that.
      ctx.effect(() => {
        const style = document.createElement('style')
        style.id = STYLE_ID
        style.textContent = STYLE_TEXT
        document.head.append(style)
        return () => {
          style.remove()
        }
      }, 'dsh-settings-resize: style')

      // Both dictionaries in one call, so the row is never half-translated. Registered before
      // the slot so the first paint already has its text.
      //
      // The locale service keeps one occupant per (namespace, language) and *throws* on a
      // duplicate. A reload can leave an earlier registration behind — an HMR pass re-runs
      // this module, which resets `registered` to undefined, and the previous generation's
      // disposer may not have fired yet. An uncaught throw here would abort the effect and
      // leave the namespace without its `zh` dictionary, so lookups fall through to the `en`
      // fallback and the row can switch to English but never back to Chinese. Release what
      // we own first, then take the namespace over even if a stale claim survives.
      const locale = ctx.get('locale')
      if (locale !== undefined) {
        ctx.effect(() => {
          // Release whatever an earlier generation of this module left behind, then claim
          // the namespace. Without this, the duplicate claim throws and the `zh` dictionary
          // never lands, so the row switches to English but cannot switch back.
          releaseDictionaries()
          const dispose = locale.register(NS, { zh: zh, en: en })
          const host = typeof globalThis !== 'undefined' ? globalThis : undefined
          if (host !== undefined) host[DISPOSER_KEY] = dispose
          return () => {
            // Only the generation that still owns the claim may release it. A retiring
            // fiber can run its cleanup after the next generation has already re-registered,
            // and releasing unconditionally would delete the fresh dictionaries.
            const owner = host !== undefined && host[DISPOSER_KEY] === dispose
            if (owner) delete host[DISPOSER_KEY]
            if (owner) dispose()
          }
        }, 'dsh-settings-resize: zh/en strings')
      }

      // Apply the remembered state as soon as the plugin starts, and take it back off when
      // the plugin stops, so the shipped dialog returns untouched.
      ctx.effect(
        () => {
          applyState(readStored())
          return () => {
            clearState()
          }
        },
        'dsh-settings-resize: size variables',
      )

      // A row inside General settings. The slot is declared by the General section at
      // runtime, so `inject` accounts for any order between the two registrations.
      // `locale` gives the component a `t` seat and re-renders the row on a language change.
      ctx.effect(
        () =>
          ctx.slots.inject('settings.general.item', () =>
            ctx.slots.register(
              {
                name: 'settings.general.item',
                id: 'settings-resize',
                order: 18,
                locale: NS,
                label: () =>
                  locale === undefined ? 'Settings window size' : locale.bind(NS)('title'),
              },
              Section,
            ),
          ),
        'dsh-settings-resize: general settings row',
      )
    }

    return {
      name: 'dsh-settings-resize',
      inject: ['slots'],
      apply: apply,
    }
  },
})

================================================================================
八、安装步骤（实测可用的方式）
================================================================================

【推荐：走 plugin_manager】
在 DSH 会话里对 Agent 说「把这个目录装成插件」，Agent 会调用
plugin_manager install_bundle，target = 插件目录绝对路径。
它内部执行 pnpm add + 选中 bundle + 重载配置，一步到位。
实测返回：
  {"stage":"enable","target":"dsh-settings-resize","enabled":true,"changed":true,
   "application":"applied","packageResult":{"exitCode":0,...},"warnings":[]}

【手工等价步骤】
1. 备份 C:\Users\HSG\.dsh\profiles\desktop\package.json。
2. dependencies 增加：
     "dsh-settings-resize": "link:E:/Data/data_dsh/2026/dsh-settings-resize"
3. dsh.profile.bundles 数组末尾追加 "dsh-settings-resize"。
4. 在 profile 目录执行 pnpm install（该 profile 实际用 pnpm，不是 npm）。
5. DSH 会自动热重载；若未生效，重启 DSH。

【红线】读写 package.json 必须走 Node（JSON.parse + fs.writeFileSync(..., 'utf8')）。
严禁用 PowerShell 的 Set-Content / Out-File 写 JSON —— 它们会写入 UTF-8 BOM，
导致 DSH 解析失败、工作空间全部消失（本机发生过一次真实事故）。
校验方法：取文件前 3 字节，应为 123,10,32（即 { LF space），不能是 239,187,191。

【停用】
在插件页关闭 dsh-settings-resize，或在 profile 的 cordis.patch.yml 里写：
  - id: dsh-settings-resize
    disabled: true
停用后设置弹窗立即回到 800 × 800、不透明、无描边。
（实测：禁用后该 occupant 从 slot 列表消失，重新启用后恢复。）

================================================================================
十、禁止事项
================================================================================

1. 不改 DSH 安装目录、不解包/改动 app.asar。
2. 不创建目录联接（junction / symlink），只做真实文件写入。
   （唯一例外：pnpm 安装时自己建的 node_modules 链接，那是包管理器行为。）
3. 不新增任何 npm 运行依赖，react 由宿主 require 提供。
4. 不用哈希类名做选择器，只用 data-shortcut-modal 属性。
5. 不把宽高/透明度写死在默认值以外的地方；实际值一律来自用户输入 + localStorage。
6. 不改动其他插件、不改动 cordis.patch.yml 里已有的条目。
7. 不要用 opacity 实现透明度（会连文字一起变淡），必须用 color-mix 混背景。
8. 不要用 border 做 100% 时的描边（会改变盒子尺寸），必须用 outline。

================================================================================
十一、开发过程中被推翻的两个最初设想（供参考，不要再走回去）
================================================================================

设想 A：新增一个左侧导航分区「窗口尺寸」
  最初要求用 ctx.slots.inject('settings.section', ...) 注册一整页，order=5。
  实际改为：注册到 settings.general.item，作为「通用」页里的一行。
  原因：用户明确要求在「通用设置」里出现滑动条，而不是新增一页。

设想 B：高度支持 px / vh 单位下拉
  实际改为只有 px。原因见第五节。
  兼容措施：normalize 仍会把老记录里的 vh 换算成 px，不会出错。
